# Apply Protocol（v0.2）

1. **单 WP**：一次只执行一个 READY WP；不得提前夹带后续 WP。
2. **基线校验**：开始前运行 `make spec-check`，校验 Lark revision、契约 checksum 与 Git commit；不一致立即停止并提交 SCR。
3. **路径 allowlist**：开始前确认目标 WP 的允许修改路径；提交只可触碰这些路径。新增路径须先更新 WP/SCR。
4. **验证失败**：任一指定命令非 0 时停止，不继续下一个 WP，不以 waiver 绕过。
5. **歧义处理**：需求、API、DDL、事件、测试或 Mock 有歧义时先提交 SCR，未批准前不得猜测实现。
6. **范围控制**：禁止无规格扩展、顺手重构或新增外部依赖；必要工作应新增 WP 并重排 DAG。
7. **证据**：每个 PR 附命令、退出码、测试报告、迁移结果、checksum、变更路径及 WP/REQ/TC/MOCK 链接。
8. **可恢复失败**：超时、限流、暂时不可用使用同一幂等键重试，自动最多 3 次，并保留状态和诊断。
9. **不可恢复失败**：契约校验、权限、恶意文件、数据损坏、基线冲突立即失败，不自动重试；需修正输入或提交 SCR。
10. **回滚**：代码/配置回退到 WP 前 commit；expand migration 可回滚，已产生数据的 contract migration 走补偿；删除和已发布外部事件不可逆，只允许前向修复。
